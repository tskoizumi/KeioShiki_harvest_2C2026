## 連絡のルール

二人で別々に作るので、**情報が流れないのがいちばんの事故**。作る速さより、連絡を優先する。

### 連絡はGitHubに集める

- 相談・決めごと・進捗は、GitHub の issue とプルリクエストに書く。QR・結果まわりは [#1](https://github.com/tskoizumi/KeioShiki_harvest_2C2026/issues/1)
- LINEや口頭で決めたことも、**その日のうちにissueに一行書き残す**。書いてないことは決まっていない扱い
- 決まったことは `docs/TECHNICAL.md` にも反映して、資料を常に最新にしておく

### 通知を必ず受け取る

- リポジトリ右上の **Watch → All Activity** にする（issue・プルリクエスト・コメントが全部届く）
- スマホに **GitHub Mobile** を入れて、プッシュ通知をオンにする
- **1日1回は通知を確認する**

### 返事のしかた

- 返事がほしいときは、必ず **`@相手のID`** をつける（`@tskoizumi` / `@soma1218`）
- **24時間以内に返す。** すぐ答えられないときも、👀 のリアクションか「見た、明日返す」の一言で「読んだ」ことを伝える
- 急ぎ（当日のトラブルなど）は、LINEで「GitHub見て」と一声かける
- 48時間返事がなければ、LINEで直接聞く

### 作業の前後に一言

- **始める前**に、issueに「これをやる」と書く（同じところを二人で触らないため）
- **終わったら**、プルリクエストを出して報告する。プルリクエストのテンプレートに沿って書く
- 相手の担当（下の「担当」の範囲）にかかるプルリクエストは、GitHubが自動で相手にレビューを頼む（`.github/CODEOWNERS`）。**レビューを頼まれたら24時間以内に見る**

### 週に一回、進捗を書く

- **毎週日曜の夜**に、#1 に進捗を書く：やったこと／次にやること／困っていること・相手に聞きたいこと
- issueの「進捗報告」テンプレートを使ってもいい

## 開発のルール

このリポジトリは**公開**されていて、`main` は**pushした瞬間に本番サイトへ反映**される。この2つを前提に、次を守る。

### 1. `main` に直接pushしない

- 作業は必ずブランチで。名前は `qr/〜`（QR・結果まわり）、`site/〜`（LP）、`fix/〜`（直し）のように頭で分ける
- 終わったらプルリクエストを出し、**もう一人が見てから**マージする
- ブランチをpushすると Cloudflare がプレビュー用のURLを出す。**スマホで開いて確認してから**マージする
- 当日（収穫祭の前日から終わりまで）は、閾値の変更などの小さな直し以外はマージしない

### 2. 秘密の情報をコミットしない

- 合言葉、Cloudflareのトークン、APIキーは**絶対にコミットしない**。本番は Cloudflare の環境変数（Secret）、手元は `.dev.vars`（`.gitignore` 済み）に入れる
- 一度pushすると、消しても履歴とフォークに残る。間違えてpushしたら、消すより先に**その鍵を無効にして作り直す**
- GitHub の Settings → Emails で「Keep my email addresses private」をオンにして、コミットにメールアドレスを載せない

### 3. 個人情報・本物のデータを入れない

- 本名、質問票の答え、当日の本物の結果は、リポジトリに入れない（データベースかスプレッドシートに置く）
- 結果の紙の番号は連番にしない（他人の結果をURLの書き換えで覗けてしまう）

### 4. 相手の担当を触るときは声をかける

- LP（`index.html` `config.js` `assets/`）を変えたいときは、プルリクエストで `tskoizumi` に見てもらう
- QR・結果まわりは `soma1218` の判断で作っていい。新しいフォルダ（`functions/` など）を足すのも自由
- 新しいライブラリ・ビルドの仕組み・外部サービスを**LP側に**足したいときは、先にissueで相談する（LPはビルドなし・依存なしで保っている）

### 5. 勝手に変えないもの

- **QRに焼き込むURL**（ドメイン・ファイル名・パラメータ名）。QRを刷ったあとは変更禁止。刷った紙が全部使えなくなる
- 独自ドメインを買うなら、QRを刷る前に設定まで済ませる

### 6. 出す前に確認する

- スマホ幅とPC幅の両方で崩れていないか
- 端末の「視差効果を減らす」をオンにしても読めるか
- `resultUrl` / `rankingUrl` を入れたとき、LPのボタンと番付がちゃんと出るか

### 7. AIを使うとき

- AIには `README.md` と `docs/TECHNICAL.md` を最初に読ませると、このルールと構成に沿って書いてくれる
- AIが書いたコードも、自分で動かして上の確認をしてからプルリクエストを出す
- AIのチャットに合言葉やトークンを貼らない

## 公開する

Cloudflare ダッシュボード → Workers & Pages → 作成 → Pages → Git に接続 → このリポジトリを選び、次の設定で保存。

| 項目 | 値 |
| --- | --- |
| フレームワークプリセット | なし |
| ビルドコマンド | （空欄） |
| ビルド出力ディレクトリ | `/` |
| 本番ブランチ | `main` |

`https://<プロジェクト名>.pages.dev/` で公開される。以後 `main` に push するたびに自動で再デプロイされる。
`main` 以外のブランチに push するとプレビュー用の別URLが出る。

QR・結果まわりでビルドや Pages Functions を使う場合は、この設定を変えてよい（変えたらここを書き直す）。

## LPとのつなぎ目

`config.js` の2つの値だけで、LPとQR・結果のシステムがつながる。

| 値 | 入れるもの | 空のとき |
| --- | --- | --- |
| `resultUrl` | 「神託を受け取る」ボタンの行き先（例: `"share.html"`） | ナビのボタンと、ページ下の「結果の紙を、お持ちですか。」を隠す |
| `rankingUrl` | 番付のデータのURL（JSON か CSV） | 番付は「開場後に更新します」のまま |

番付のデータの形は [docs/TECHNICAL.md の「番付のデータ」](docs/TECHNICAL.md#番付のデータ) を参照。

## よく触る設定（`config.js`）

- **日時・場所・公式アカウント**: `date` `place` `instagram`。出し物名 `name` はナビやフッターに入るが、トップの大きなロゴは画像（`assets/layer-copy.webp`）に焼き込まれているので、名前を変えるならロゴも作り直す
- **改竄の閾値**: `kaizanThreshold`。LPの位の表と、番付の赤い表示がこれに従う。QR・結果側でも同じ値を使うなら、ここから読んでもらう
- **ミニゲームを止める**: 該当ゲームの `enabled` を `false` に。チンチロが止められたらこれで消える
- **的当てを無料にする**: `fee` を `"無料"` に
