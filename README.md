# 運命、賄賂で買いませんか？ — 収穫祭2026 2年C組 公式サイト

ビルド不要の静的サイト。Cloudflare Pages で公開する。

**一緒に開発する人は、先に下の「開発のルール」と [docs/TECHNICAL.md](docs/TECHNICAL.md)（技術資料）を読んでください。** 技術資料には構成・データ形式・各ページの仕組み・QRシステムとの接続案をまとめてあります。

## 開発のルール

このリポジトリは**公開**されていて、`main` は**pushした瞬間に本番サイトへ反映**される。この2つを前提に、次を守る。

### 1. `main` に直接pushしない

- 作業は必ずブランチで。名前は `qr/〜`（QRシステム）、`site/〜`（サイト）、`fix/〜`（直し）のように頭で分ける
- 終わったらプルリクエストを出し、**もう一人が見てから**マージする
- ブランチをpushすると Cloudflare がプレビュー用のURLを出す。**スマホで開いて確認してから**マージする
- 当日（収穫祭の前日から終わりまで）は、閾値の変更などの小さな直し以外はマージしない

### 2. 秘密の情報をコミットしない

- 合言葉、Cloudflareのトークン、APIキーは**絶対にコミットしない**。本番は Cloudflare の環境変数（Secret）、手元は `.dev.vars`（`.gitignore` 済み）に入れる
- 一度pushすると、消しても履歴とフォークに残る。間違えてpushしたら、消すより先に**その鍵を無効にして作り直す**
- GitHub の Settings → Emails で「Keep my email addresses private」をオンにして、コミットにメールアドレスを載せない

### 3. 個人情報・本物のデータを入れない

- 本名、質問票の答え、当日の本物の結果は、リポジトリに入れない（データベースかスプレッドシートに置く）
- 結果の紙の番号は連番にしない（ランダムな英数字）

### 4. 決まった場所を触る

- 占いの文章 → `oracle.js`、サイトの設定や数値 → `config.js`。HTMLに値を直書きしない
- 書き方は今のコードに合わせる：素のJS、ビルドなし、依存パッケージなし、コメントは日本語
- 新しいライブラリ・ビルドの仕組み・外部サービスを足したいときは、**先にissueで相談**する

### 5. 勝手に変えないもの（変えるなら先に相談）

- QRの行き先 `share.html?id=<番号>` のファイル名・パラメータ名・ドメイン。**QRを刷ったあとは変更禁止**（刷った紙が全部使えなくなる）
- 結果データの形 `id, name, sou, kizashi, amount, oracle`。サイトとQRシステムの両方が使っている

### 6. 出す前に確認する

- スマホ幅とPC幅の両方で崩れていないか
- `share.html?id=DEMO01`（小）／`DEMO02`（大）／`DEMO03`（改竄）でシェア画像が出るか
- `teller.html` で心付けを変えて、台本が4パターン（無・小・大・改竄）出るか
- 端末の「視差効果を減らす」をオンにしても読めるか

### 7. AIを使うとき

- AIには `README.md` と `docs/TECHNICAL.md` を最初に読ませると、このルールと構成に沿って書いてくれる
- AIが書いたコードも、自分で動かして上の確認をしてからプルリクエストを出す
- AIのチャットに合言葉やトークンを貼らない

### 8. 相談と記録

- 相談・決めごとは GitHub の issue でする（QRシステムとの接続は [#1](https://github.com/tskoizumi/KeioShiki_harvest_2C2026/issues/1)）
- 決まったことは `docs/TECHNICAL.md` に反映して、資料を常に最新にしておく

## 公開する

Cloudflare ダッシュボード → Workers & Pages → 作成 → Pages → Git に接続 → このリポジトリを選び、次の設定で保存。

| 項目 | 値 |
| --- | --- |
| フレームワークプリセット | なし |
| ビルドコマンド | （空欄） |
| ビルド出力ディレクトリ | `/` |
| 本番ブランチ | `main` |

`https://<プロジェクト名>.pages.dev/` で公開される。以後 `main` に push するたびに自動で再デプロイされる（番付・閾値の更新もこれで反映）。
`main` 以外のブランチに push するとプレビュー用の別URLが出るので、大きな変更はそちらで確かめてから `main` に入れる。

**QRを刷ったあとは公開先（プロジェクト名）を変えないこと。** 変えると刷ったQRが全部読めなくなる。

## よく触る設定（`config.js`）

- **日時・場所・公式アカウント**: `date` `place` `instagram`。出し物名 `name` はサイト全体とシェア画像に入るが、トップの大きなロゴ画像（`assets/layer-copy.webp`）には焼き込まれているので、名前を変えるならロゴも作り直す。
- **改竄の閾値**: `kaizanThreshold`。サイトの位の表、番付の朱色表示、シェア画像のデザイン切り替えがすべてこれに従う。昼に上げ下げするならここを書き換えて push。
- **ミニゲームを止める**: 該当ゲームの `enabled` を `false` に。チンチロが止められたらこれで消える。積みは単独で本命として成立するように書いてある。
- **的当てを無料にする**: `fee` を `"無料"` に。

## 番付の更新

`data/ranking.json` を書き換えて push する（1時間ごと）。

```json
{
  "updatedAt": "2026-11-03T13:00:00+09:00",
  "firstTitle": "神託を買った者",
  "entries": [
    { "name": "ぽんず", "amount": 3200 },
    { "name": "たかし", "amount": 1800 }
  ]
}
```

順番は気にしなくていい（額で並べ替える）。11人以上入れても上位10人だけ出る。

## 結果データとQR

QRの中身は次のURL。`id` が結果の紙の番号。

```
https://<プロジェクト名>.pages.dev/share.html?id=番号
```

- **番号は連番にしない**。`0001, 0002…` だと他人の結果をURLの書き換えで覗ける。`K7Q2XM` のようなランダムな英数字6桁を事前に作って紙に刷り、その番号とデータを紐づける。
- QRが読めない人のために、番号は紙にも文字で印刷しておく（`share.html` で手入力できる）。
- `data/results.json` に `DEMO01`〜`DEMO03` の見本が入っている（`share.html?id=DEMO03` で改竄デザインが見られる）。本番前に消す。

### 当日はスプレッドシートで入力するのがおすすめ

JSONを毎回 push するのは当日には向かない。Googleスプレッドシートを使うと、書記がシートに1行足すだけで反映される。

1. 1行目に次の見出しを入れたシートを作る

   | id | name | sou | kizashi | amount | oracle |
   | --- | --- | --- | --- | --- | --- |
   | K7Q2XM | ぽんず | 深海 | 沈黙 | 3200 | 沈黙は破られた。あなたは浮上する。 |

   （`name` はニックネーム、`sou` は相、`kizashi` は兆、`amount` は心付け額、`oracle` は神託の一行）
2. ファイル → 共有 → **ウェブに公開** → そのシートを **CSV** で公開
3. 出てきたURLを `config.js` の `resultsCsvUrl` に貼って push

番付も同じやり方ができる（見出しは `name` `amount`、任意で `title` `updatedAt`。URLは `rankingCsvUrl` へ）。

注意: ウェブ公開したCSVは反映まで数分かかることがある。番号が見つからないときは「書記の入力を少し待って」と表示されるようにしてある。また、CSVのURLは `config.js` に書く以上だれでも見られるので、シートの中身は実質公開になる（`data/results.json` も同じ）。番号をランダムにしても全体は読めてしまう前提で、ニックネーム以外の個人情報（質問票の回答など）は絶対に入れない。

## 占いの仕組み（`oracle.js`）

- **相（8つ）**: 判定用9問を3つの軸（感情で動く／変化を好む／人に向かう）に3問ずつ割り当て、各軸の合計が10以上かどうかで 2×2×2＝8 通りに落とす。焚き火・刃・深海・霧・岩・風・鏡・種。
- **兆（10枚）**: 灯・裂け目・沈黙・鈴・鍵・鳥・月・砂・足音・糸。吉・凶・混がある。
- **台本**: 相の描写（常に真顔で正確）→ 兆の解釈（兆の基本文＋相ごとの一文、80通り）→ 結論（位で変わる）。
- **言及**: 言及用10問のうち、3から遠い答えを位に応じて1〜3個拾い、相の描写の途中で「〜に5と答えましたね」と刺す。全部3だと「逃げましたね」。
- **位ごとの違い**: 無＝言及1つ・相別の一文なし・助言なし。小＝言及2つ・助言。大＝言及3つ・言及のたびに持ち上げ・悪い兆は「あなたの責任ではない」。改竄＝小と同じに読んでから鈴を鳴らし、相ごとの新しい神託を読む。シェア画像の一行もそれに差し替わる。

## ブースの流れ（`teller.html`）

1. 受付で `questionnaire.html` を印刷した質問票を渡し、番号とニックネームを書いてもらう
2. 客が入室したら、占い師（または隣の書記）が `teller.html` の「入力」に番号・ニックネーム・19問の答えを押す。受付で相まで決めてあるなら「相を直接指定」でもいい
3. 客が札を引いたら「兆」で押す
4. 盆の縁を数えて「心付け」に入れる。位が出る
5. 「台本を出す」。演じ方の指示と三部の台本が出る。改竄なら赤い枠で鈴の指示が出る
6. 読み終えたら「記録する」。この端末に残り、結果シート用の1行（id,name,sou,kizashi,amount,oracle）がコピーされる
7. 書記はときどき「記録」からCSVをコピーして結果シートに貼る。貼った分は share.html から開けるようになる

`teller.html` と `questionnaire.html` はトップページからリンクしていないが、URLを知れば誰でも開ける。台本の中身を客に見られたくなければ、URLを出し物の外で共有しないこと。
